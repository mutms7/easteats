# Saved-search UI audit

Three passes completed against the web implementation. The screen captures use clearly fictional browser fixtures, not claims about real restaurants. The implementation plan is [saved-searches-architecture.md](saved-searches-architecture.md).

## Pass 1: navigation and hierarchy

Your searches now leads the returning experience, with up to five recent named buttons, an All searches disclosure and a distinct New search action. Opening a conversation restores its stored inputs and restaurants. It clears the active source intent, including after a questionnaire/profile update. Completed source intents also clear, so returning from Taste or Saved does not restart discovery.

New search opens a free draft. A saved home can be preselected, and location, query, cuisine, food type, distance and price can be chosen before the explicit Start search action. Returning searches keep query/refinement controls closed under Adjust search, so the food list leads. Changing any combination of filters or query stays free until the explicit Search submit, which creates one new conversation/run. Refresh uses the applied input, ignores unsent drafts, keeps the current conversation ID and creates a fresh source-run ID. A one-time, account/context-guarded history GET updates delayed titles after source completion; it is not a polling interval and does not invoke a source or model.

Cards no longer show Why this place, prose match reasons, meters or score bars. Five labeled circles stay visible. Known zero is shown as 0 out of 100; missing evidence uses a dashed circle and Unknown. Each circle has a complete accessible image label. Like/Dislike, bookmark Save and Eat here have separate controls. Liked places and Saved places have separate sections.

## Pass 2: phone, desktop and keyboard

Inspected full-page screenshots at 390px and 1440px widths. Five score columns fit on desktop; phone scores form a 3+2 grid. Labels remain visible without opening details. White score numerals on flame #E12D12 have approximately 4.58:1 contrast. Unknown circles are visually distinct and never receive a zero value.

The first capture exposed a desktop navigation overlay across score labels. Desktop navigation now sits in the header, with its DOM position before main content. Phone navigation retains its bottom placement. The count/Refresh row was tightened to prevent broken phone labels. A final hierarchy check found the expanded query/filter panel pushed food below 875px on a phone. Adjust search is now closed by default and the redundant heading area action was removed; the browser check requires the first restaurant to start above 600px at 390x844. Recent-search buttons scroll horizontally; the complete history list closes on selection and focus moves to the opened search heading. Inputs, filters, opinion buttons and the history disclosure remain keyboard controls. The skip link is clipped until keyboard focus and appears at viewport y=8.

The captures are generated by `tests/e2e/saved-searches.spec.ts` as `saved-search-phone.png` and `saved-search-desktop.png` inside Playwright's test-results folder. They are disposable verification artifacts. In the isolated test environment the map key is intentionally absent, so the captured map fallback is expected. Real tiles are not verified by these mocked screenshots.

## Pass 3: complete journeys and stale work

Browser regressions cover latest-search restoration with zero discovery requests; opening a different stored search; editing taste without starting source work; explicit Start; refresh identity; new-query identity; and history switching while an older discovery response is held back. The late response cannot replace the selected stored list.

Opinion tests cover Like, undo, Dislike, the Liked collection and separation from bookmarks. They verify no discovery is invoked by feedback. Opinion writes are serialized, and an older bootstrap feedback response cannot overwrite a new vote. A stored-snapshot refresh failure does not falsely report that a successfully saved opinion was lost.

Meal tests verify Eat here does not immediately display a rating prompt, the next visit does, Not yet defers only that visit, and Neutral saves with answerMeal=true. Home-address tests retain privacy and account persistence checks while changing their expected return behavior: the latest stored conversation wins over an automatic home scrape. Explicit GPS remains behind an action and prepares a draft rather than skipping confirmation.

Verification completed during this pass: web typecheck, 15 UI helper tests, 14 combined home/history browser regressions, plus the updated discovery-map, location and demo journey coverage in the preceding run. After the final fold/batching refinement, five targeted browser checks passed, including no source calls for draft changes, one combined submit, applied-only Refresh, first-card placement, and a late specialist keeping relevance priority. The final complete referee/CI run is performed by the integrating task after all backend and native changes land. Native device execution and store readiness are outside these web screenshot checks.
