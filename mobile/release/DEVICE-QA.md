# Required native acceptance checks

Run on a current iPhone and Android device with a production-configured development/preview build. Record device/OS, build ID, tester and result. Nothing here is marked passed merely because JavaScript exports succeeded.

1. Fresh install opens login with readable type, no clipping under large system text, screen reader labels and 44pt/48dp touch targets. Missing public configuration explains why login is disabled.
2. Google opens the system browser, cancellation leaves a usable login, and a successful exact callback signs into the same Supabase account as web. A foreign scheme, host, path, fragment token or missing code cannot establish a session. Reopen after an interrupted sign-in and test app cold starts.
3. After Apple configuration, native Continue with Apple works on a physical signed iPhone, including private relay email, cancellation, second sign-in and an existing linked account. No sign-in method is falsely advertised as working before provider setup.
4. Add a restaurant, choose reasons and a goal, write notes, restart and confirm the unfinished draft. Save, inspect the interpreted profile, correct it, switch to Taste and confirm favorites and goal remain. Sign out, use another account and confirm drafts/saved places cannot leak between accounts.
5. Address typing shows predictions without starting a scraper. A selected full address starts one search intent. Deny location permission and still use the manual address path. Grant approximate or precise foreground location and check the area. Choose a typed address while GPS is pending and verify a late GPS result cannot overwrite it.
6. Cold discovery shows searching, then progressive places and pins. All current matching places appear without another submit. Old cached rows disappear after source completion. Same intent uses the same search ID during polling; explicit search/filter/location changes create a new ID. Background the app, return, and confirm polling/refresh behavior is bounded. Source failure is not labeled successful empty results.
7. Valid MapTiler credentials display real tiles and attribution on both OSes. All pins fit and names can be read. A blocked/missing key produces a truthful fallback with a usable restaurant list. Check a single result, no results, many results, and two points near the antimeridian.
8. Save/unsave persists to the server. Relaunch signed in with connectivity disabled and confirm the encrypted offline saved copy is labeled stale. Directions opens a real destination and Share uses the native sheet. Missing photos have a truthful placeholder; no fixture ratings appear.
9. Account deletion Cancel leaves data intact. Confirmed deletion sends only `confirmation: DELETE`, removes the authenticated account/data on the server, and clears the local session and caches only on success. Server failure leaves the user signed in with an actionable error. Repeat on an Apple-created account after configuring any required Apple token revocation.
10. Inspect the final signed Android merged permissions and iOS entitlements/privacy manifests. Only foreground location should prompt for discovery. No background tracking, microphone, camera/photo-library or advertising identifier permission should be requested. Verify HTTPS calls, no secret keys in artifacts/logs and no production development menu.
11. Public privacy and deletion links work without the installed app. Store review credentials/access work against the deployed backend. Capture real screenshots from each platform, without personal data or claims the app cannot demonstrate.
